{# List toolbar, 44px (spec §5.3, mockup layout.html `.om-lbar`): tri-state select-all, refresh, overflow, then the range and the pager. **Two bars, one at a time.** With a selection the toolbar becomes the selection's (`list/toolbar_selected.html`); with none it is this one. Both are in the document and Alpine's `x-show` picks between them, rather than htmx swapping one in: the swap would be a round trip for a state the browser already knows, and it would fight the selection it was rendering — every checkbox click would replace the toolbar under the reader's pointer. `x-show` reads `$store.list.count`, a plain number app.js writes in `render()`, not `selected.size`. It is also written this way round on purpose: this bar is the *default*, so it carries no `x-cloak` and is visible before Alpine starts (and on a page whose Alpine never starts at all), while the selection bar is cloaked and only ever appears once there is something to show it for. **The bare `x-data` is load-bearing.** Alpine only initializes trees rooted at `[x-data]`/`[x-init]` — `start()` walks `document.querySelectorAll(allSelectors())`, not the whole body — so a standalone `x-show` is never evaluated at all. It does not warn and it does not throw: the element simply keeps whatever the stylesheet gave it, which for the cloaked bar means invisible forever. Checked in the browser, where it was already failing exactly that quietly. Empty is the right value: this bar's state lives in a store, not in a component, and the CSP build allows no inline methods in `x-data` anyway. #}
