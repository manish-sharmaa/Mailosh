{# One conversation row (spec §5.3, mockup layout.html `.om-row`) — the markup contract Tasks 9-11 bind to, so the attribute set here is deliberate rather than incidental: `data-id` is the thread id every selection/keyboard operation keys off; `data-email-ids` is the *whole* conversation, which is what an action operates on, while `data-count` is the number of messages in the mailbox being viewed (`ThreadRow.count`) — never `len(email_ids)`, which spans messages that are not in this view at all. `role="row"` + `aria-selected` complete the roving-tabindex grid `list/page.html` opens. The roving `tabindex` starts here rather than in JS: `list.render()` in app.js only ran on `htmx:afterSettle`, which does not fire on a first full page load, so the shipped page contained zero `tabindex="0"` and the list could not be reached by Tab at all (review finding B1). The first row of a *page* render carries the 0 — that is the only render that can be the whole document. A `standalone` render is the `/rows` fragment, which is either the endless-scroll append (where a second 0 would be wrong) or the `mail:changed` refresh (which cannot happen without JS at all); app.js owns the tab stop in both, as it does for every row after the first. Row controls (check, star, hover actions) carry a `data-action` hook and the keyboard hint in their tooltip (spec §6.1's "Archive (e)"). One delegated listener in static/js/actions.js reads those hooks and runs the action, and static/js/keys.js's registry reaches the same code from the keyboard. Nothing has to stop their clicks from also opening the conversation: they are siblings of the stretched anchor below and paint above it, so a click on one never reaches it. Every one of them is `tabindex="-1"`, which is the other half of the grid the row opens. They were all natively focusable, and `.row:focus-within` *revealed* the three hover actions part-way through a traversal, so a measured tab-walk stopped five times per row — roughly 251 stops on a 50-row page, for a list whose focused row then did nothing, because nothing bound `Enter`. In an ARIA grid the row is the tab stop and the arrow keys reach its cells: `ArrowRight`/`ArrowLeft` walk these controls (app.js), `Enter`/`o` opens the conversation (keys.js). Two of them are two-way, and each says so in the DOM rather than needing the client to guess: the star's `aria-pressed` is what turns a click into `on=0` instead of `on=1`, and `.row.is-unread` is what picks between the pair of mail buttons at the end of the row. #}
