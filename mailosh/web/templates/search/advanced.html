{# The advanced panel (spec §10: From, To, Subject, Has the words, Doesn't have, Size, Date within, Search in, Has attachment). **It writes a query, it does not build a filter.** Every field here becomes operator text — `from:x`, `subject:"y"`, `-z`, `larger:5m`, `newer_than:1m` — which `GET /search/build` composes and hands to the same parser a typed query goes through (`mailosh.web.search._build_query`). Two consequences worth stating: the panel can offer "Doesn't have" without this app learning a second way to say NOT, and the results it lands on are a real, shareable `/search?q=…` URL that the reader could have typed themselves. A panel that assembled JMAP conditions directly would have neither. A plain GET `
` with a real `action`, so it works with no JavaScript; htmx upgrades the same submit to a `#main` swap. `static/js/search.js` closes the surrounding `
` afterwards — the one thing a disclosure cannot do for itself. Prefilled from the query being viewed, best-effort: a query the nine boxes cannot round-trip (an `OR`, a parenthesised group, two `from:` terms) still searches exactly as typed — the panel shows the part of it that fits, and submitting replaces the query with what the boxes say. That is the same bargain Gmail's panel makes, and the reason the pill above it never stops being the authoritative way to write one. #}
