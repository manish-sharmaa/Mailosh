{# The compose component itself (design spec §8) — the fields, the editor, the attachment row and the bottom toolbar. `compose/dock.html` and `compose/inline.html` are the two frames around it and are the *only* difference between a corner dock and a reply card at the end of a conversation; everything a reader actually types into is here, once. --------------------------------------------------------------------- Why this is markup and `static/js/compose.js` is behaviour The app's CSP is `script-src 'self'` with no `'unsafe-eval'`, and what is vendored is Alpine's **CSP build**, so this file carries no inline expression that needs an evaluator: no `hx-on:`, no `hx-vals='js:…'`, no `x-on`/`x-show`, and no `x-data` object literal with methods in it. The single directive here is a bare `x-data="compose"` naming a component registered with `Alpine.data()` — which is exactly the shape the CSP build exists to serve, and which gives the component the `init`/`destroy` pair a Squire instance needs (spec §8: "owning a Squire instance in a closure ... `destroy` -> `editor.destroy()`"). Everything else is `data-role`/`data-field` hooks read by one delegated listener, the same model `static/js/actions.js` and `app.js` already use. --------------------------------------------------------------------- Autosave is htmx's, and nothing else here is `hx-post="/compose/draft"` with `hx-trigger="input delay:2s"` and `hx-sync="this:replace"` is spec §8's autosave, verbatim: `input` bubbles from every field *and* from the contenteditable editor up to this form, `delay` restarts on each one (so the timer measures "since the last edit", not "since the first"), and `this:replace` means a save that is still in flight when the next one comes due is abandoned rather than raced. `hx-target` is this dock's own state chip and nothing else. No compose request in this app ever targets `#main`, and none pushes a URL — a draft in progress is not a place, and the inbox behind it must keep working while it is open. Send, discard and the attachment upload are `fetch`/`XHR` from `compose.js` rather than htmx, for the reason `actions.js` documents for its own six: those responses have no body to swap, and send in particular is a *delayed* commit whose request must not exist until the undo window has run out. --------------------------------------------------------------------- The body is seeded from a hidden input, not from the DOM `data-html` carries the draft's HTML as an attribute value (escaped by Jinja, so nothing in it is parsed as markup here) and `compose.js` puts it through DOMPurify and into Squire. A reply quotes a message a stranger wrote; rendering that HTML into this document even once — before Squire has sanitised anything — is the one thing a mail client may never do. #} {% macro recipient(field, person) %} {# One chip. `static/js/compose.js` builds byte-identical markup when a chip is committed client-side, so a reopened draft and a freshly typed address are the same element with the same hooks.
