{# The dedicated print page (spec §7's Print), served by `GET /t/{thread_id}/print`. Its own lean document rather than `layouts/app.html` or `layouts/bare.html`: the app layout is the chrome this page exists to be without, and bare.html centres a single card in the viewport, which is a sign-in form's shape and not a document's. What is left is the head both share — charset, viewport, the compiled `app.css` — and nothing else. No htmx, no Alpine, no nav, no toolbar, no dock, no toasts: there is nothing on this page to act on. `data-theme="light"` is fixed, and is not the reader's preference being overruled — it is the medium. Paper is white, so the page and every message frame on it render light regardless of how the app is set (the frames are asked for `?theme=light` for the same reason). Density is left at the token default for the same reason; a printout has no comfortable/compact. **Every message is expanded, and expanded here means rendered, not revealed.** `styles/print.css` prints the *reading* view by opening its folds under `@media print`, and it cannot do more than that: a collapsed card's body was never fetched (`thread/message.html` asks for each frame on `intersect once`), so opening it on paper prints an empty box. This page has no folds at all — no `
`, no lazy frames, no `•••` pill — so there is nothing left to open. For the same reason there are no controls. The star, the ⋮ menu, the attachment chips' Download/Open buttons and the recipient disclosure are all things to press, and paper cannot be pressed: the headers they hide are printed outright, and the attachments are named in a list rather than drawn as chips with buttons on them. #} {{ view.subject }} — Mailosh {# The recipient macros, from the one template that spells "me" and `Name ` the way this app spells them — the same import `thread/details.html` makes, so the printed header reads identically to the disclosure on screen instead of being a second copy of the same six lines. `with context` because `person()` reads `me`. #} {% from "thread/people.html" import people with context %}
