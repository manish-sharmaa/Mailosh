{# The strips that sit above a framed message body (spec §7): the blocked-remote-images banner, and the dark-restyle "Original colours" toggle. Both live here because they are one visual component in two states, and each **self-guards on its own context**, so an include that supplies neither renders nothing at all. That is what lets the same file be included from two places with two different scopes: - from `thread/frame.html`, INSIDE `#frame-{{ email_id }}`, with `blocked_remote`/`remote_hosts`/`sender`. The remote strip has to be inside that wrapper, because its own two controls swap the wrapper `outerHTML` — a strip outside it would survive its own dismissal and sit there claiming images are blocked while they load underneath. - from `thread/message.html`, OUTSIDE that wrapper and inside `#frame-area-{{ email_id }}`, with `restyle_sender`. The restyle strip has to be outside, because the sender it posts is known only to the conversation view — `GET /m/{id}/frame` renders `thread/frame.html` with no sender in scope, so a strip inside the wrapper would vanish the first time "Show images" swapped it and never come back. Pass each set inside its own `with` block. Jinja's include inherits the whole surrounding context, so a `restyle_sender` left in scope around the frame include would reach this file a second time through `thread/frame.html` and draw the restyle strip twice. --------------------------------------------------------------------- No JavaScript, on purpose "Show images" is a plain `hx-get` of `/m/{id}/frame?remote=1` and "Always show from" is a plain form `hx-post`; both target the wrapper by id and swap it whole. That is not a stylistic preference: the CSP serves `script-src 'self'` with no `'unsafe-eval'`, which rules out htmx's `hx-on:`/`hx-vals='js:…'` (compiled with `new Function`), and Alpine's CSP build would reject an inline expression too. A control built out of attributes htmx already understands is the one shape that cannot fail silently in the browser. The address goes in a hidden field rather than `hx-vals`: `hx-vals` would have to carry JSON through an HTML attribute, and a `From` header is sender-controlled text — one `"` in it and the JSON stops parsing, with no error anywhere. A form field is escaped by Jinja and URL-encoded by htmx, whatever the header says. --------------------------------------------------------------------- What the copy may and may not claim `blocked_remote` counts `` loads, and `remote_hosts` is the deduplicated host list behind exactly those loads. Those references are gone rather than deferred — "Show images" cannot bring them back either. So the second line is scoped to the images this banner is actually about ("They would load from …") and never to trackers in general.
