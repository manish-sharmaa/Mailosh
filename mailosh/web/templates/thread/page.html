{# `data-email-ids` is what makes the action bar above real. The routes in mailosh/web/actions.py take *message* ids; `data-thread-id` is not one, so a page carrying only that gave static/js/actions.js nothing to post and its three buttons did nothing at all. Same attribute name, same comma-separated shape and same meaning as `list/row.html`'s — the whole conversation, which is what an action on it operates on — so the one delegated listener reads a row and a thread the same way. `data-unread-ids` is the subset the mark-read-on-open POST has work to do on — the whole conversation would be a wider write than the reader asked for, and a noisier `Email/set` for the server. The scroll target is marked on the card itself (`data-first-unread`), not named again here: one attribute, one reader, no way for the two to disagree about which message the conversation opens at. `data-mark-read-delay` is the reader's own setting in seconds, and static/js/actions.js arms one timer from it on settle — `0` marks on arrival, `-1` never marks at all. It sits on this element rather than on the body because that handler keys the timer off *which conversation* is on screen (`data-thread-id`, beside it): one element carrying both is what stops a timer armed for the conversation you just left from firing against the one you are now reading. `data-advance-url` is where archiving or deleting this conversation lands (spec §10's `auto_advance`), resolved by the route because only it knows this conversation's neighbours. One finished URL, so the client reads an attribute instead of re-deriving a decision from the readout above. #}
