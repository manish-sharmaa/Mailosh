{# The full-page answer to a `JmapError`/`TransportError` (design spec §9: "a global exception handler returns an OOB toast fragment for HTMX requests and a friendly page otherwise"). Rendered by `mailosh.web.app._error_page`, which owns the status code — `502` when the mail server never answered at all, `500` when it answered with a failure — so nothing about the status is written here. Two things it deliberately does NOT have, both because an exception handler runs outside every route's dependencies and can reach neither the session nor the database: 1. **No `prefs`, no `user`, no `csrf_token`.** So this extends nothing: `layouts/bare.html` renders `data-theme`/`data-density` off `prefs` and a CSRF meta tag, none of which exist here. Leaving `data-theme` off entirely is the *right* answer rather than a compromise — styles/input.css's dark block matches `:root:not([data-theme=light])`, so an unset attribute is exactly "follow the OS", which is what a page that cannot read the reader's saved theme should do. 2. **No scripts.** The one affordance here is a link, and a page whose job is to survive a broken backend should not depend on htmx, Alpine or a store being alive to offer it. `retry_url` is this same request's own address, so "Retry" is one click rather than a manual reload.
